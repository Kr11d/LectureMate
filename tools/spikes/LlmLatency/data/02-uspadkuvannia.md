# Лекція 2. Успадкування

[стор. 5]

## 2.1. Що таке успадкування

Успадкування — це механізм, за якого новий клас (нащадок, похідний клас) отримує поля й методи наявного класу (базового, батьківського) і може додати власні або змінити успадковану поведінку. Між нащадком і базовим класом виникає відношення «є» (is-a): кожен нащадок є різновидом базового класу. Квадрат є фігурою, студент є людиною, PDF-документ є матеріалом курсу.

У C# клас може мати лише один базовий клас, але може реалізовувати довільну кількість інтерфейсів. Якщо базовий клас не вказано, ним неявно є `System.Object`, тому будь-який об'єкт має методи `ToString`, `Equals` і `GetHashCode`.

```csharp
public class Shape
{
    public string Name { get; }

    protected Shape(string name) => Name = name;

    public virtual double Area() => 0;

    public override string ToString() => $"{Name}: площа {Area():F2}";
}

public class Circle : Shape
{
    public Circle(double radius) : base("Коло") => Radius = radius;

    public double Radius { get; }

    public override double Area() => Math.PI * Radius * Radius;
}

public class Rectangle : Shape
{
    public Rectangle(double width, double height) : base("Прямокутник")
    {
        Width = width;
        Height = height;
    }

    public double Width { get; }
    public double Height { get; }

    public override double Area() => Width * Height;
}
```

[стор. 6]

Конструктор нащадка обов'язково викликає конструктор базового класу через `base(...)`. Спочатку виконується конструктор бази, потім — конструктор нащадка. Так гарантується, що успадкована частина об'єкта ініціалізована раніше, ніж нащадок почне нею користуватися.

## 2.2. Перевизначення методів

Метод, позначений у базовому класі як `virtual`, нащадок може перевизначити словом `override`. Метод без `virtual` перевизначити не можна: його можна лише приховати оголошенням `new`, але це майже завжди погана ідея, бо поведінка тоді залежить від типу змінної, а не від типу об'єкта.

Перевизначений метод може викликати базову реалізацію через `base.Method()`. Це корисно, коли нащадок не замінює поведінку повністю, а лише доповнює її — наприклад, додає власний рядок до результату `ToString`.

Слово `sealed` забороняє подальше успадкування класу або перевизначення конкретного методу. Робити класи `sealed` за замовчуванням — добра практика: успадкування має бути свідомим рішенням автора класу, а не випадковою можливістю. Клас, не спроєктований для успадкування, легко зламати в нащадку, бо нащадок залежить від деталей реалізації бази.

## 2.3. Ієрархії класів

Набір класів, пов'язаних успадкуванням, утворює ієрархію. У прикладі вище ієрархія складається з трьох класів: `Shape`, `Circle` і `Rectangle`. Добра ієрархія неглибока (два-три рівні) і широка: багато нащадків одного базового класу, кожен із чітко окресленою відмінністю.

[стор. 7]

Глибокі ієрархії на п'ять і більше рівнів важко зрозуміти й змінювати. Щоб дізнатися, що робить метод у класі нижнього рівня, доводиться переглядати всі класи вгору по ієрархії. Зміна в базовому класі може непередбачувано вплинути на десятки нащадків. Цю проблему називають «крихким базовим класом» (fragile base class).

Ознаки того, що успадкування використано невдало:

- нащадок перевизначає метод бази так, що той кидає `NotSupportedException`;
- нащадок не використовує більшу частину успадкованих членів;
- ієрархію побудовано заради повторного використання коду, а не через відношення «є»;
- щоб додати нову комбінацію ознак, потрібно створювати новий клас (наприклад, `RedSmallCircle`, `BlueLargeCircle`).

## 2.4. Композиція замість успадкування

Композиція — це відношення «має» (has-a): об'єкт містить інші об'єкти як поля і делегує їм частину роботи. Автомобіль має двигун, а не є двигуном. Сесія лекції має джерело звуку і транскрибер, а не є ними.

Принцип «надавайте перевагу композиції перед успадкуванням» не забороняє успадкування. Він радить використовувати успадкування лише для справжнього відношення «є» і для поліморфізму, а повторне використання коду здебільшого досягати композицією. Композицію легше змінювати: компонент можна замінити іншим під час виконання, а базовий клас — ні.

[стор. 8]

```csharp
public sealed class ReportGenerator
{
    private readonly IFormatter _formatter;

    public ReportGenerator(IFormatter formatter) => _formatter = formatter;

    public string Build(Report report) => _formatter.Format(report);
}
```

Тут `ReportGenerator` не успадковує форматування, а отримує форматувальник ззовні. Щоб змінити формат звіту з Markdown на CSV, достатньо передати інший об'єкт, і код генератора не зміниться.

## 2.5. Шаблонний метод як приклад доречного успадкування

Існує ситуація, у якій успадкування особливо корисне: коли кілька класів мають однаковий алгоритм, що відрізняється лише окремими кроками. Базовий клас реалізує загальний алгоритм у невіртуальному методі, а змінні кроки оголошує абстрактними або віртуальними. Нащадки реалізують лише ці кроки. Такий підхід називають патерном «Шаблонний метод» (Template Method), ми детально розглянемо його в лекції про патерни.

**Підсумок лекції.** Успадкування моделює відношення «є» і дає змогу перевизначати поведінку через віртуальні методи. Ієрархії мають бути неглибокими; класи, не призначені для успадкування, варто позначати `sealed`. Для повторного використання коду частіше підходить композиція.
