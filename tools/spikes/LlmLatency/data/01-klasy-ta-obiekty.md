# Лекція 1. Класи, об'єкти та інкапсуляція

[стор. 1]

## 1.1. Від процедур до об'єктів

Процедурна програма складається з даних і функцій, які ці дані обробляють. Поки програма невелика, такий підхід зручний: дані лежать у структурах, функції приймають їх як параметри і повертають результат. Проблеми починаються тоді, коли кількість функцій зростає до сотень. Будь-яка функція може змінити будь-яке поле, і щоб зрозуміти, чому структура опинилася в некоректному стані, доводиться переглядати весь код. Зміна формату даних тягне за собою зміни в десятках місць.

Об'єктно-орієнтоване програмування пропонує інший спосіб організації коду. Дані й операції над ними об'єднуються в одне ціле — об'єкт. Об'єкт сам відповідає за свій стан і надає назовні лише ті операції, які мають сенс для його користувачів. Код, що працює з об'єктом, не знає, як саме той зберігає дані, і тому не залежить від цих подробиць.

Три класичні ідеї ООП — інкапсуляція, успадкування і поліморфізм. До них часто додають абстракцію: уміння виділити суттєві для задачі властивості й відкинути решту. У цій лекції ми почнемо з базових понять: клас, об'єкт, поле, метод, конструктор і модифікатори доступу.

## 1.2. Клас і об'єкт

Клас — це опис типу: які дані зберігає кожен його екземпляр і які операції над ним можна виконувати. Об'єкт — конкретний екземпляр класу, що існує під час виконання програми і займає пам'ять. Клас можна порівняти з кресленням будинку, а об'єкт — з будинком, збудованим за цим кресленням. За одним кресленням можна збудувати багато будинків, і кожен матиме власну адресу та власних мешканців.

[стор. 2]

У мові C# клас оголошується ключовим словом `class`:

```csharp
public class BankAccount
{
    private decimal _balance;

    public BankAccount(string owner, decimal initialBalance)
    {
        if (initialBalance < 0)
            throw new ArgumentOutOfRangeException(nameof(initialBalance));
        Owner = owner;
        _balance = initialBalance;
    }

    public string Owner { get; }
    public decimal Balance => _balance;

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(amount));
        _balance += amount;
    }

    public void Withdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance)
            throw new InvalidOperationException("Недостатньо коштів або некоректна сума.");
        _balance -= amount;
    }
}
```

Поле `_balance` зберігає стан об'єкта. Методи `Deposit` і `Withdraw` змінюють цей стан, але тільки за правилами, які встановив сам клас: сума поповнення має бути додатною, а зняти більше, ніж є на рахунку, не можна. Конструктор гарантує, що об'єкт від самого початку перебуває в коректному стані.

## 1.3. Поля, властивості та методи

Поле — це змінна, оголошена всередині класу. Кожен об'єкт має власну копію полів екземпляра. Статичні поля, позначені словом `static`, належать класу в цілому й існують в одному примірнику.

Властивість у C# виглядає для користувача як поле, але насправді є парою методів: `get` для читання і `set` (або `init`) для запису. Властивості дозволяють перевіряти значення, обчислювати їх на льоту або зробити поле доступним лише для читання. Автоматична властивість `public string Owner { get; }` створює приховане поле, яке компілятор генерує сам.

[стор. 3]

Метод описує поведінку об'єкта. Корисно розрізняти методи-запити, які повертають інформацію і не змінюють стан, та методи-команди, які змінюють стан і зазвичай нічого не повертають. Таке розділення (принцип command–query separation) робить код передбачуванішим: виклик запиту ніколи не має побічних ефектів.

Конструктор — спеціальний метод, який викликається під час створення об'єкта. Його головне завдання — встановити інваріанти, тобто умови, що мають виконуватися протягом усього життя об'єкта. Для банківського рахунку інваріант звучить так: баланс ніколи не буває від'ємним. Якщо конструктор приймає некоректні аргументи, він має кинути виняток, а не створювати «напівготовий» об'єкт.

## 1.4. Інкапсуляція

Інкапсуляція — це приховування внутрішнього стану об'єкта і надання доступу до нього лише через контрольований інтерфейс. Мета інкапсуляції не в тому, щоб «сховати» дані від інших програмістів, а в тому, щоб захистити інваріанти. Якби поле `_balance` було публічним, будь-який код міг би записати в нього від'ємне число, і перевірки в методі `Withdraw` втратили б сенс.

Інкапсуляція має й другу перевагу: вона зменшує зв'язність коду. Якщо завтра ми вирішимо зберігати баланс у копійках як `long`, а не як `decimal`, зміниться лише внутрішня реалізація класу. Код, що викликає `Deposit` і читає `Balance`, залишиться без змін.

Модифікатори доступу в C#:

- `public` — член доступний усім;
- `private` — лише всередині класу (типове значення для членів класу);
- `protected` — усередині класу та його нащадків;
- `internal` — у межах однієї збірки (проєкту);
- `protected internal` і `private protected` — комбінації попередніх.

[стор. 4]

Практичне правило: починайте з найсуворішого модифікатора і послаблюйте його лише тоді, коли з'являється реальна потреба. Поля майже завжди мають бути `private`. Публічними роблять методи та властивості, що утворюють контракт класу.

Типова помилка початківців — створювати для кожного приватного поля пару публічних методів `GetX` і `SetX`. Формально поле приховане, але фактично будь-хто може записати в нього що завгодно, тож інкапсуляції немає. Замість сеттерів краще давати методи, що описують намір: не `SetBalance`, а `Deposit` і `Withdraw`.

## 1.5. Незмінні об'єкти та записи

Об'єкт, стан якого не можна змінити після створення, називають незмінним (immutable). Незмінні об'єкти простіше аналізувати: їх можна безпечно передавати між потоками, використовувати як ключі словника й не боятися, що хтось змінить їх «за спиною». У C# для незмінних типів даних зручно використовувати записи (`record`):

```csharp
public sealed record Point(double X, double Y);
```

Запис автоматично отримує конструктор, властивості лише для читання, порівняння за значенням (`Equals`, `GetHashCode`) і зручний метод `ToString`. Щоб отримати змінену копію, використовують вираз `with`: `var moved = point with { X = 10 };`. Записи добре підходять для об'єктів передачі даних (DTO), подій і результатів обчислень, а класи з інкапсульованим змінним станом — для сутностей із поведінкою.

**Підсумок лекції.** Клас описує дані та поведінку, об'єкт — конкретний екземпляр. Інкапсуляція захищає інваріанти об'єкта і зменшує залежність коду від деталей реалізації. Поля роблять приватними, а назовні надають методи, які описують дії предметної області.
