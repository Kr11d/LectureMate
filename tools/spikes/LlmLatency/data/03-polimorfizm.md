# Лекція 3. Поліморфізм: динамічний і статичний

[стор. 9]

## 3.1. Ідея поліморфізму

Слово «поліморфізм» означає «багато форм». У програмуванні це здатність коду працювати з об'єктами різних типів через спільний інтерфейс, не знаючи конкретного типу кожного об'єкта. Клієнтський код пише «обчисли площу фігури», а яка саме формула спрацює — для кола чи для прямокутника — визначається автоматично.

Поліморфізм — головна причина, чому ООП полегшує розширення програм. Щоб додати новий вид фігури, достатньо створити новий клас; код, що обходить список фігур і підсумовує площі, змінювати не потрібно. Це пряме втілення принципу відкритості/закритості, про який ітиметься в лекції про SOLID.

Розрізняють два основні види поліморфізму:

- **динамічний** (поліморфізм підтипів): реалізація обирається під час виконання програми залежно від фактичного типу об'єкта. У C# він реалізується через віртуальні методи та інтерфейси;
- **статичний** (параметричний поліморфізм): той самий код працює з різними типами, а конкретний тип підставляється під час компіляції. У C# це узагальнені типи й методи (generics).

Іноді до статичного поліморфізму відносять також перевантаження методів — кілька методів з однаковою назвою, але різними параметрами. Компілятор обирає потрібне перевантаження за типами аргументів.

## 3.2. Динамічний поліморфізм і віртуальні методи

Розглянемо клієнтський код для ієрархії фігур із попередньої лекції:

```csharp
IReadOnlyList<Shape> shapes = [new Circle(1), new Rectangle(2, 3), new Circle(0.5)];
double total = 0;
foreach (Shape shape in shapes)
{
    total += shape.Area();
}
```

[стор. 10]

Змінна `shape` має тип `Shape`, але виклик `shape.Area()` виконує метод фактичного класу об'єкта. Як це працює? Для кожного класу з віртуальними методами середовище виконання будує таблицю віртуальних методів (vtable) — масив адрес реалізацій. Кожен об'єкт містить посилання на опис свого типу, а отже й на таблицю. Під час виклику віртуального методу програма бере таблицю фактичного типу об'єкта і переходить за адресою з потрібної комірки. Такий виклик називають пізнім, або динамічним, зв'язуванням.

Віртуальний виклик трохи повільніший за звичайний, бо потребує додаткового непрямого переходу, і компілятору складніше його вбудувати (inline). У більшості програм ця різниця непомітна. Сучасний JIT-компілятор .NET уміє в багатьох випадках «девіртуалізувати» виклик, якщо доведе, що фактичний тип відомий, наприклад, для класу з модифікатором `sealed`.

## 3.3. Поліморфізм через інтерфейси

Інтерфейс — це контракт: набір методів і властивостей, які зобов'язується надати кожен клас, що його реалізує. Клієнтський код, який залежить від інтерфейсу, може працювати з будь-якою реалізацією, у тому числі з тією, що з'явиться через рік, або з тестовою заглушкою.

```csharp
public interface IExporter
{
    string FileExtension { get; }
    void Export(Summary summary, Stream output);
}

public sealed class MarkdownExporter : IExporter { /* ... */ }
public sealed class CsvExporter : IExporter { /* ... */ }

public void Save(Summary summary, IExporter exporter, string path)
{
    using var stream = File.Create(Path.ChangeExtension(path, exporter.FileExtension));
    exporter.Export(summary, stream);
}
```

[стор. 11]

Метод `Save` не знає, у якому форматі зберігається конспект. Вибір формату робить користувач у вікні програми, а `Save` залишається незмінним. Це і є поліморфізм у дії: одна точка виклику, багато реалізацій.

## 3.4. Статичний поліморфізм: узагальнені типи

Узагальнений (generic) тип має параметр-тип, який підставляється під час використання. Класичний приклад — `List<T>`: один і той самий код списку працює з `List<int>`, `List<string>` і `List<Student>`. Компілятор перевіряє типи на етапі компіляції, тож у `List<int>` неможливо додати рядок, а під час читання не потрібне приведення типу.

Узагальнення бувають не лише в колекціях. Ось буфер, що зберігає лише елементи за останні N секунд:

```csharp
public interface ITimestamped
{
    TimeSpan Start { get; }
    TimeSpan End { get; }
}

public sealed class TimeWindowBuffer<T> where T : ITimestamped
{
    private readonly Queue<T> _items = new();
    private readonly TimeSpan _window;

    public TimeWindowBuffer(TimeSpan window) => _window = window;

    public void Add(T item)
    {
        _items.Enqueue(item);
        while (_items.Count > 0 && item.End - _items.Peek().End > _window)
            _items.Dequeue();
    }

    public IReadOnlyList<T> Snapshot() => _items.ToArray();
}
```

Обмеження `where T : ITimestamped` повідомляє компілятору, що будь-який тип `T` має властивості `Start` і `End`. Завдяки цьому всередині класу можна звертатися до `item.End`. Без обмеження компілятор дозволив би лише операції, доступні для будь-якого `object`. Інші види обмежень: `where T : class` (лише посилальні типи), `where T : struct` (лише типи-значення), `where T : new()` (є конструктор без параметрів), `where T : SomeBaseClass`.

## 3.5. Узагальнені методи

Параметр-тип може мати і окремий метод. Наприклад, метод повтору операції з експоненційною затримкою не залежить від типу результату операції:

```csharp
public static async Task<T> ExecuteAsync<T>(Func<CancellationToken, Task<T>> operation,
                                            int maxAttempts, CancellationToken ct)
{
    for (var attempt = 1; ; attempt++)
    {
        try { return await operation(ct); }
        catch (Exception) when (attempt < maxAttempts)
        {
            await Task.Delay(TimeSpan.FromSeconds(Math.Pow(2, attempt - 1)), ct);
        }
    }
}
```

Зазвичай тип `T` компілятор виводить сам з аргументів, тож явно писати `ExecuteAsync<string>(...)` не потрібно.

## 3.6. Порівняння двох видів поліморфізму

| | Динамічний | Статичний |
|---|---|---|
| Коли обирається реалізація | Під час виконання | Під час компіляції |
| Механізм у C# | `virtual`/`override`, інтерфейси | generics, перевантаження |
| Перевірка типів | Частково під час виконання | Повністю компілятором |
| Типове застосування | Змінна поведінка, плагіни, стратегії | Колекції, алгоритми, утиліти |

Обидва види часто поєднують: узагальнений клас з обмеженням на інтерфейс використовує статичний поліморфізм для типу елементів і динамічний — для виклику методів інтерфейсу.

**Підсумок лекції.** Поліморфізм дозволяє писати клієнтський код один раз для багатьох типів. Динамічний поліморфізм обирає реалізацію під час виконання через таблицю віртуальних методів, статичний — під час компіляції через узагальнення. Обмеження `where` визначають, які операції доступні для параметра-типу.
