# Лекція 6. Патерни проєктування

[стор. 22]

## 6.1. Що таке патерн

Патерн проєктування — це перевірене рішення типової задачі проєктування, описане так, щоб його можна було застосувати в різних програмах. Патерн не є готовим кодом чи бібліотекою: це ідея, яку кожного разу втілюють з урахуванням конкретної ситуації. Класичний каталог із 23 патернів опублікувала 1994 року «банда чотирьох» (Gang of Four): Е. Гамма, Р. Гелм, Р. Джонсон і Дж. Вліссідес. Патерни поділяють на три групи: породжувальні (як створювати об'єкти), структурні (як компонувати об'єкти) і поведінкові (як розподіляти обов'язки між об'єктами).

Патерн варто застосовувати тоді, коли він розв'язує проблему, яка у вас справді є. Код, у якому патернів більше, ніж задач, складніший за код без патернів.

## 6.2. Стратегія (Strategy)

**Задача.** Є кілька варіантів алгоритму або поведінки, і потрібно обирати між ними під час виконання, не переписуючи код, який ними користується.

**Рішення.** Кожен варіант виноситься в окремий клас, що реалізує спільний інтерфейс. Клієнт (контекст) зберігає посилання на інтерфейс і делегує йому роботу. Стратегію можна передати в конструкторі або замінити пізніше.

```csharp
public interface IAudioSource
{
    Task StartAsync(CancellationToken ct);
    Task StopAsync();
}

public sealed class SystemSoundSource : IAudioSource { /* захоплення звуку ПК */ }
public sealed class MicrophoneSource : IAudioSource { /* мікрофон */ }
public sealed class WaveFileSource : IAudioSource { /* відтворення WAV-файлу */ }
```

[стор. 23]

Сесія лекції отримує `IAudioSource` і не знає, звідки береться звук. Користувач обирає джерело у випадному списку, а для тестів і демонстрацій підставляється відтворення WAV-файлу. Стратегія — це, по суті, поліморфізм через інтерфейс, застосований до змінної поведінки.

## 6.3. Шаблонний метод (Template Method)

**Задача.** Кілька класів виконують однаковий алгоритм, у якому різняться лише окремі кроки. Копіювання спільних кроків у кожен клас призводить до дублювання й помилок.

**Рішення.** Базовий клас реалізує алгоритм у невіртуальному методі й викликає з нього абстрактні або віртуальні кроки. Нащадки реалізують лише ці кроки.

```csharp
public abstract class ExporterBase
{
    public async Task ExportAsync(Summary summary, Stream output, CancellationToken ct)
    {
        ArgumentNullException.ThrowIfNull(summary);
        if (!output.CanWrite)
            throw new ArgumentException("Потік не підтримує запис.", nameof(output));
        await WriteAsync(summary, output, ct);
        await output.FlushAsync(ct);
    }

    protected abstract Task WriteAsync(Summary summary, Stream output, CancellationToken ct);
}
```

Перевірки, обробка помилок і завершальні дії написані один раз у базовому класі, а нащадок `MarkdownExporter` відповідає лише за формат. Відмінність від стратегії: шаблонний метод використовує успадкування і фіксує структуру алгоритму в базі, стратегія використовує композицію і замінює алгоритм цілком.

## 6.4. Стан (State)

**Задача.** Поведінка об'єкта залежить від його стану, а допустимі операції змінюються зі станом. Наприклад, сесію можна поставити на паузу лише тоді, коли вона запущена, а відновити — лише з паузи.

**Рішення.** Явно описати стани й дозволені переходи між ними. У повній формі патерну кожен стан — окремий клас; у простіших випадках достатньо перелічення станів і таблиці дозволених переходів, яку перевіряє один метод. Головне — не розкидати перевірки стану по всьому коду у вигляді численних `if`.

```csharp
private static readonly Dictionary<SessionState, SessionState[]> Allowed = new()
{
    [SessionState.Idle]    = [SessionState.Starting],
    [SessionState.Running] = [SessionState.Paused, SessionState.Stopping, SessionState.Faulted],
    [SessionState.Paused]  = [SessionState.Running, SessionState.Stopping],
};
```

## 6.5. Фабрика (Factory)

**Задача.** Клієнт має створювати об'єкти, але не повинен знати, який саме клас створювати: це залежить від налаштувань, середовища чи режиму роботи.

**Рішення.** Створення об'єктів винести в окремий клас або метод-фабрику, що повертає інтерфейс. Наприклад, фабрика провайдерів у режимі «Демо» повертає імітації, які працюють без мережі, а в робочому режимі — справжні клієнти сервісів. Код, що користується провайдерами, однаковий в обох режимах.

[стор. 25]

## 6.6. Спостерігач (Observer)

**Задача.** Один об'єкт змінюється, і про це мають дізнатися інші об'єкти, причому джерело не повинно залежати від конкретних отримувачів.

**Рішення.** Джерело надає механізм підписки, а отримувачі підписуються на сповіщення. У C# спостерігач вбудований у мову у вигляді подій (`event`):

```csharp
public sealed class LectureSession
{
    public event EventHandler<TranscriptSegment>? SegmentReceived;

    private void OnSegment(TranscriptSegment segment) => SegmentReceived?.Invoke(this, segment);
}
```

Модель представлення вікна підписується на подію й оновлює список транскрипту. Сесія при цьому нічого не знає про інтерфейс користувача. Важливо пам'ятати, що обробник події виконується в потоці джерела, тож оновлення інтерфейсу треба передавати в UI-потік через диспетчер.

## 6.7. Репозиторій (Repository)

**Задача.** Бізнес-логіка має зберігати й шукати об'єкти, не залежачи від конкретного способу зберігання (SQL, файли, пам'ять).

**Рішення.** Інтерфейс сховища з операціями предметної області: «знайти сесії за курсом», «додати сегменти до лекції». Реалізація використовує конкретну технологію, наприклад Entity Framework Core. Узагальнений репозиторій поверх ORM, що просто дублює методи `DbContext`, зазвичай не додає цінності: краще мати специфічні сховища з методами, потрібними саме цій програмі.

[стор. 26]

## 6.8. MVVM

Model–View–ViewModel — архітектурний патерн для програм із графічним інтерфейсом, особливо поширений у WPF. Представлення (View) описане в XAML і містить лише розмітку. Модель представлення (ViewModel) зберігає стан екрана у властивостях і надає команди; представлення прив'язується до них через механізм зв'язування даних (data binding). Модель (Model) — це предметна логіка та сервіси. Завдяки такому розділенню логіку інтерфейсу можна тестувати без вікон, а дизайн вікна змінювати, не чіпаючи логіки.

**Підсумок лекції.** Патерни — це словник перевірених рішень. Стратегія і фабрика дозволяють обирати реалізацію під час виконання, шаблонний метод прибирає дублювання алгоритму, стан упорядковує переходи, спостерігач розв'язує джерело й отримувачів, репозиторій ізолює зберігання даних, MVVM відокремлює логіку від інтерфейсу.
