# Інструкції для ШІ-агента (LectureMate)

Цей файл агент читає автоматично на початку кожної сесії. Повний контекст: [HANDOFF.md](HANDOFF.md). Розклад: [PLAN.md](PLAN.md). Промпти дня: [PROMPTS.md](PROMPTS.md).

## Перед роботою
- Прочитай розділи HANDOFF.md, названі в промпті дня; правила з розділу 17 діють завжди.
- Працюй у гілці `feature/<коротко>` від свіжого `main`. Якщо зараз `main`, створи гілку.
- Не чіпай файли зони партнера (розподіл у HANDOFF §15) без явної потреби; якщо доводиться, напиши про це в описі PR.

## Команди
```
dotnet build
dotnet test
dotnet format --verify-no-changes
```
Тести з `[Trait("Category", "Live")]` потребують API-ключів у змінних середовища й пропускаються без них.

## Обмеження
- `Core` залежить лише від BCL і `Microsoft.Extensions.Logging.Abstractions`.
- Нові NuGet-пакети: тільки з HANDOFF §11; будь-який інший спершу погодь із користувачем.
- Тексти інтерфейсу лише в `.resx`; код, назви та XML-коментарі англійською.
- Жодних ключів у коді, тестах, логах, комітах. У логах промпти лише як довжина + хеш.
- Не додавай абстракцій «на майбутнє» (HANDOFF §6.5).

## Чекліст завершення задачі
1. Збірка без попереджень, усі тести зелені, `dotnet format` чистий.
2. Кожен новий `public` тип і член має XML-документацію; кожна нова поведінка має тест.
3. `ELEMENTS.md`: дописано нові елементи й оновлено підсумкову таблицю.
4. `AI_USAGE.md`: рядок із датою, роллю (A/B), задачею, що згенеровано, що змінено вручну.
5. Нова бібліотека → рядок у `LIBRARIES.md` (версія, можливості, де в коді) і запис у `RETROSPECTIVE.md`.
6. Коміти в стилі Conventional Commits англійською; PR з описом нетривіальних рішень, щоб партнер міг їх захистити.
7. Наприкінці коротко поясни користувачу, що зроблено і які рішення варто знати на захисті.
